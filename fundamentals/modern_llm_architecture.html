Modern LLM Architecture

Beyond "It's Just a Transformer"

Why This Matters

Everyone says "it's just embedding → MHA → MLP → LM head." That's the 2017 answer. Modern LLMs (LLaMA 3, Mistral, DeepSeek-V2, Gemma 2) have diverged significantly in how attention works, how KV is cached, and how training is stabilized. These are the follow-up questions that separate "I've read the blog post" from "I've built systems."

1. KV Cache Efficiency: GQA, MQA, MLA

The problem: during autoregressive inference, you cache K and V for every past token so you don't recompute them. For long sequences, this cache dominates GPU memory.

Standard MHA (Multi-Head Attention)

Every Q head has its own K head and V head. 32 heads = 32 K + 32 V = 64 projections cached.

Q heads: Q₁ Q₂ Q₃ Q₄ Q₅ Q₆ ... Q₃₂ K heads: K₁ K₂ K₃ K₄ K₅ K₆ ... K₃₂ ← 32 K to cache V heads: V₁ V₂ V₃ V₄ V₅ V₆ ... V₃₂ ← 32 V to cache KV cache per token = 32 × 2 × head_dim × 2 bytes

GQA (Grouped Query Attention)

Group Q heads to share KV heads. E.g., every 4 Q heads share 1 KV group → 8 KV groups instead of 32.

Q heads: Q₁ Q₂ Q₃ Q₄ │ Q₅ Q₆ Q₇ Q₈ │ ... │ Q₂₉ Q₃₀ Q₃₁ Q₃₂ KV group: KV₁ │ KV₂ │ ... │ KV₈ 32 Q heads, 8 KV groups → 4:1 ratio KV cache: 8 instead of 32 → 4x reduction

Used by: LLaMA 2 70B, LLaMA 3, Mistral. Almost no quality loss vs full MHA.

MQA (Multi-Query Attention)

Extreme case: all Q heads share a single K and a single V.

Q heads: Q₁ Q₂ Q₃ Q₄ Q₅ ... Q₃₂ KV: KV₁ ← just 1 K + 1 V for all heads 32:1 ratio. Minimal KV cache but some quality loss.

Used by: PaLM, Falcon. Aggressive — works but GQA is the safer choice.

MLA (Multi-head Latent Attention)

DeepSeek-V2's approach: don't cache K and V at all. Instead, compress them into a low-rank latent vector and cache that.

Standard: cache K (d_head per head) + V (d_head per head) MLA: cache c_KV (one small latent vector per token) At attention time: decompress c_KV → K, V on the fly c_KV = W_down × [K; V] (compress) K, V = W_up × c_KV (decompress) Cache size: d_latent instead of 2 × n_heads × d_head e.g., 512 instead of 8192 → 16x reduction

Even more aggressive than GQA. The decompression adds compute but the memory savings are massive for long contexts.

2. Sliding-Window Attention

Full attention: every token attends to all previous tokens. Cost = O(n²). KV cache grows without bound.

Sliding window: each layer only attends to the last W tokens (e.g., W=4096).

Full attention (token at position 10000): attends to: [0, 1, 2, ..., 9999] ← everything KV cache: 10000 entries, unbounded Sliding window (W=4096): attends to: [5904, 5905, ..., 9999] ← last 4096 only KV cache: 4096 entries, always bounded

But how do you get long-range context?

Stack layers. Each layer's window overlaps with the previous layer's window. Information propagates through the stack:

Layer 3: sees tokens [t-W, t] but those tokens carry info from Layer 2 Layer 2: sees tokens [t-W, t] but those carry info from Layer 1 Layer 1: sees tokens [t-W, t] raw Effective context at Layer L = L × W 32 layers × 4096 window = 131K effective context Even though each layer only looks at 4096 tokens!

Used by: Mistral 7B (W=4096), Gemma 2 (alternating with full attention).

The tradeoff: bounded memory and O(n·W) compute vs. slightly weaker direct long-range connections. For most tasks, the stacked propagation is sufficient.

3. Hybrid Attention Patterns

The 2025-2026 insight: not every layer needs the same attention pattern. Alternate between cheap local attention and expensive global attention.

Gemma 2 / Mistral-style hybrid: Layer 0: [sliding window] ← local patterns, cheap, bounded KV Layer 1: [sliding window] Layer 2: [FULL attention] ← global reasoning, expensive, full KV Layer 3: [sliding window] Layer 4: [sliding window] Layer 5: [FULL attention] ← global reasoning ... Ratio: ~1 full : 2 sliding Result: ~60% of the KV cache cost, ~95% of the quality

Why this works: most layers are learning local patterns (syntax, local dependencies) that don't need global context. Only a few layers need to do global reasoning (resolving coreferences, long-range dependencies).

Interview one-liner: "Not every layer needs full attention. Hybrid architectures alternate sliding-window layers (cheap, local) with full attention layers (expensive, global). You get most of the quality at a fraction of the KV cache cost."

4. Training Stability: QK-Norm

The problem: as models get larger, attention logits Q · K⊃T can grow to extreme values. Large logits → softmax saturates → vanishing gradients → training instability.

Without QK-Norm: Q · Kᵀ = [2.1, -0.3, 847.2, 1.5, ...] ← one huge value softmax → [0.0, 0.0, 1.0, 0.0, ...] ← collapsed, gradient ≈ 0 With QK-Norm: Q_norm = RMSNorm(Q) K_norm = RMSNorm(K) Q_norm · K_normᵀ = [0.8, -0.1, 2.1, 0.5] ← bounded softmax → [0.3, 0.1, 0.4, 0.2] ← distributed, healthy gradient

Applied before the dot product, per head. Just normalize Q and K vectors independently. Trivial to implement, significant impact at scale.

Used by: Gemma 2, Cohere Command R, Chameleon. Becoming standard for 10B+ models.

Note: this is different from the 1/sqrt(d_k) scaling in vanilla attention. That's a fixed scalar. QK-Norm is a learned normalization of the actual Q and K vectors.

5. Positional Encoding: RoPE, NoPE, Hybrid

RoPE (Rotary Position Embedding)

The current standard. Encodes position by rotating Q and K vectors by an angle proportional to their position. Two tokens close together have similar rotations → high dot product. Far apart → different rotations → lower dot product.

Key property: the attention score between positions i and j depends only on their relative distance (i-j), not absolute position. This is what makes length extrapolation possible.

Used by: LLaMA, Mistral, Qwen, most modern LLMs.

NoPE (No Positional Encoding)

Some layers use no positional encoding at all. The model relies on causal masking alone for position information — token at position 5 can see positions 0-4, token at position 6 can see 0-5. That asymmetry provides an implicit ordering signal.

Hybrid: RoPE + NoPE across layers

Layer 0: RoPE ← position-aware Layer 1: NoPE ← position-free, learns content-only patterns Layer 2: RoPE Layer 3: NoPE ... Why: some layers benefit from position (local syntax), others don't need it (semantic similarity is position-independent).

Emerging research direction. The intuition: forcing every layer to be position-aware is wasteful. Some attention patterns (e.g., "find the most similar concept anywhere in context") are better off without positional bias.

6. A Modern LLM Layer (2025-2026)

Input x │ ├─→ RMSNorm ├─→ Q, K, V projections │ ├─ Q: 32 heads (full) │ └─ K, V: 8 groups (GQA, 4:1 ratio) ├─→ RoPE on Q, K (or NoPE for some layers) ├─→ QK-Norm on Q, K ├─→ Attention (sliding window OR full, depends on layer) ├─→ Output projection ├─→ Residual + RMSNorm ├─→ FFN (SwiGLU: gate × up projection, then down projection) │ └─ or MoE: router picks top-2 experts, each is a SwiGLU FFN └─→ Residual Output

Compare to vanilla 2017 transformer: LayerNorm (not RMSNorm), full MHA (not GQA), sinusoidal position (not RoPE), ReLU FFN (not SwiGLU), no QK-Norm, no sliding window, no MoE.

The Interview Answer

"Modern LLMs have diverged significantly from vanilla transformers in three areas. KV efficiency: GQA groups query heads to share KV, reducing cache by 4x; sliding-window attention bounds cache size regardless of sequence length; hybrid architectures alternate local and global attention layers. Training stability: QK-Norm prevents attention logit explosion at scale; RMSNorm replaces LayerNorm; pre-norm is standard. Sparsity: MoE decouples model capacity from compute cost — I've trained MoE models, the key insight is you get the representational power of a much larger model at a fraction of the inference cost."
