The Gist

Cross-EntropyHow much probability did you put on the right answer? logsumexp(x) - x_correct. No softmax anywhere.

MSE Loss

Error → square → mean over all dimensions → scalar.

def mse_loss(pred, target):
    # pred: (B, S, D), target: (B, S, D) → scalar
    return ((pred - target) ** 2).mean()
.mean() with no dim → reduces everything to scalar. No dim argument. No keepdim.

Softmax

Convert logits to probabilities: subtract max (stability), exp, normalize.

def softmax(logit):
    # logit: (B, S, D) → (B, S, D) probabilities summing to 1 along D
    logit = logit - logit.max(dim=-1, keepdim=True).values
    nom = torch.exp(logit)                         # element-wise, no dim
    denom = nom.sum(dim=-1, keepdim=True)
    return nom / denom

The keepdim Rule

Use keepdim=True whenever you reduce a dim and then broadcast back against the original tensor.

Mental check: "Am I about to do math between this result and the original tensor?" If yes → keepdim=True.

In softmaxWhy keepdim?
logit.max(dim=-1, keepdim=True).valuesSubtracting from (B,S,D) → needs (B,S,1) not (B,S)
nom.sum(dim=-1, keepdim=True)Dividing into (B,S,D) → needs (B,S,1)

When you DON'T need it:

  • Final scalar: .mean() in MSE — done, no broadcasting after
  • Both sides lose the same dim: cross-entropy's logsumexp(dim=-1) and gather both produce (B,S)

Ops that reduce (and might need keepdim): .max(dim=), .min(dim=), .sum(dim=), .mean(dim=), .var(dim=), .norm(dim=)

Gotcha: .max(dim=) returns a named tuple (values, indices). You must write .max(dim=-1, keepdim=True).values — forgetting .values is a common bug.

Cross-Entropy

The derivation that avoids softmax entirely

Naive: -log(softmax(x)[correct]) = -log( exp(x_c) / sum(exp(x)) ) = -( x_c - log(sum(exp(x))) ) ← log and exp cancel on numerator! = log(sum(exp(x))) - x_c = logsumexp(x) - x_correct ← final formula, no softmax
def xentropy(logit, label):
    # logit: (B, S, D), label: (B, S) → (B, S)
    right_logit = torch.gather(logit, dim=-1, index=label.unsqueeze(-1)).squeeze(-1)
    return torch.logsumexp(logit, dim=-1) - right_logit

Add .mean() at the end to match F.cross_entropy's scalar output.

gather — The Indexing Pattern

gather requires the index to have the same number of dimensions as the input.

logit: (B, S, D) ← 3D label: (B, S) ← 2D → gather refuses! label.unsqueeze(-1): (B, S, 1) ← 3D → gather works result: (B, S, 1) ← 3D .squeeze(-1): (B, S) ← clean

Pattern: unsqueeze to satisfy gather's dim requirement, squeeze to clean up.

dim=-1 in gather tells it which dimension to index into (the class dimension D).

Why not torch.arange for 3D?

For 2D (B, C): logit[torch.arange(B), label] works cleanly — both indices have length B.

For 3D (B, S, D): you'd need arange(B) and arange(S) paired into B*S combinations — messy. Use gather instead.

torch.logsumexp — Stability for Free

torch.logsumexp internally does the max-subtraction trick. You don't need to subtract max yourself.

If you wrote log(sum(exp(x))) by hand → yes, you'd need x - x.max(). But with torch.logsumexp → free.

No keepdim needed on logsumexp here — both logsumexp and gather collapse the D dimension, so (B,S) - (B,S) matches.

Activation Normalization: RMSNorm & LayerNorm

Both normalize activations (not weights) along the feature dimension D. For each (b, s) position, they normalize the D-dimensional vector.

RMSNorm

Divide by root-mean-square, then scale. No mean centering, no bias.

def rmsnorm(x, gamma):
    # x: (B, S, D), gamma: (D,)
    x_rms = x / torch.sqrt(torch.mean(x ** 2, dim=-1, keepdim=True))
    return x_rms * gamma

What I got wrong

  • torch.sqrt is element-wise — no dim arg, just like torch.exp. Compute RMS manually: (x**2).mean(...).sqrt()
  • Lost the original x — computed RMS but then assigned it to x instead of dividing x by it
  • .sum() instead of .mean() — root mean square, not root sum square
  • Normalize first, scale second — (x / x_rms) * gamma, not (x * gamma) / x_rms

LayerNorm

Subtract mean, divide by std, then scale + shift. Save mu once — it's used in both numerator and denominator.

def layernorm(x, gamma, beta):
    # x: (B, S, D), gamma: (D,), beta: (D,)
    mu = x.mean(dim=-1, keepdim=True)
    x_ln = (x - mu) / torch.sqrt(torch.mean((x - mu) ** 2, dim=-1, keepdim=True))
    return x_ln * gamma + beta

What I got wrong

  • Forgot to subtract mean in the numerator — wrote x / denom instead of (x - mu) / denom. The whole point is zero-centering first.
  • Parenthesis bug: wrote x - mu ** 2 (squares the mean) instead of (x - mu) ** 2 (squares the difference)
  • Dropped eps during rewrites — always add it before .sqrt()
  • Computed mu multiple times — save it to a variable, reuse in numerator and denominator
unbiased gotcha: .mean() on squared diffs divides by N (population variance). This matches nn.LayerNorm. If you ever use .var() instead, you must pass unbiased=False — PyTorch defaults to unbiased=True (divides by N-1), which won't match.

Stats Foundation: Variance, Std, RMS, Scale

SSE = sum((xi - x_mean)**2) subtract, square, sum variance = SSE / N average the squared deviations std = sqrt(variance) = sqrt(mean((x - x_mean)**2)) scale = mean(x**2) average squared values (no centering) RMS = sqrt(scale) = sqrt(mean(x**2))

std = sqrt(mean((x - x_mean)**2)) — spread around the mean

RMS = sqrt(mean(x**2)) — spread around zero

LayerNorm divides by std → unit std (exact zero mean + unit variance).

RMSNorm divides by RMS → unit scale (mean(x**2) = 1 after normalization).

If the mean is zero, std = RMS. Otherwise RMS is slightly larger.

Element-wise Ops — No dim!

These ops are purely element-wise. They do not take a dim argument:

torch.exp, torch.sqrt, torch.log, torch.abs, torch.clamp, ** 2

If you need to reduce along a dimension, combine with .mean(dim=) or .sum(dim=) first, then apply the element-wise op.
