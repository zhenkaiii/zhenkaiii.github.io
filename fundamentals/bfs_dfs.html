BFS for Binary Trees (Level-Order Traversal)

The key idea is that a single queue to stash offspring is not enough. You may need two! Swap them within the while loop to make the traversal progress. 

curr_queue = [root]   # current level gives offspring
while curr_queue:
    next_queue = []   # collect ALL offspring from curr_queue
    for n in curr_queue:
        if n.left:  next_queue.append(n.left)
        if n.right: next_queue.append(n.right)

    # do whatever you need for all nodes at the same level here

    curr_queue = next_queue   # now the kids become mature to give offspring too

This "two-queue swap" pattern ensures that each iteration of the loop handles exactly one level of the tree. It provides full visibility of all nodes on that level before moving to the next, which is essential when performing cross-parent operations (such as linking cousins via .next pointers).

General Graph BFS (Shortest Path in Unweighted Graphs)

BFS finds the shortest path in an unweighted graph. The template uses a single deque plus a visited set. Mark nodes as visited when enqueueing, not when dequeueing — otherwise you'll process duplicates. 

from collections import deque

def bfs(graph, start):
    visited = {start}
    queue = deque([start])
    dist = {start: 0}

    while queue:
        node = queue.popleft()
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)       # mark BEFORE enqueue
                queue.append(neighbor)
                dist[neighbor] = dist[node] + 1

    return dist

When do you need level-by-level vs. single queue? If you only care about shortest distances, a single deque suffices — the distance is tracked per node. The two-queue (or len(queue) loop) pattern is needed when you must process an entire "wave" together, e.g., multi-source BFS or counting levels.

Multi-Source BFS

Initialize the queue with all source nodes at once. The BFS then expands outward from all sources simultaneously, finding the shortest distance from any source to every cell. Classic example: "01 Matrix" — distance of each cell to nearest 0. 

queue = deque()
dist = {}
for r in range(rows):
    for c in range(cols):
        if grid[r][c] == 0:
            queue.append((r, c))
            dist[(r, c)] = 0

while queue:
    r, c = queue.popleft()
    for dr, dc in [(0,1),(0,-1),(1,0),(-1,0)]:
        nr, nc = r + dr, c + dc
        if 0 <= nr < rows and 0 <= nc < cols and (nr, nc) not in dist:
            dist[(nr, nc)] = dist[(r, c)] + 1
            queue.append((nr, nc))

DFS — Recursive

DFS explores as deep as possible before backtracking. On trees, recursion is natural and clean: 

def dfs(node):
    if not node:
        return
    # pre-order: process node here
    dfs(node.left)
    # in-order: process node here
    dfs(node.right)
    # post-order: process node here

On general graphs, add a visited set: 

def dfs(graph, node, visited):
    visited.add(node)
    for neighbor in graph[node]:
        if neighbor not in visited:
            dfs(graph, neighbor, visited)

DFS — Iterative (with Explicit Stack)

Converting recursion to an explicit stack avoids stack overflow on deep graphs and gives you more control over traversal order. 

def dfs_iterative(graph, start):
    visited = {start}
    stack = [start]

    while stack:
        node = stack.pop()
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                stack.append(neighbor)

Caveat: iterative DFS with a stack visits nodes in a different order than recursive DFS (it processes the last-pushed neighbor first). For most problems this doesn't matter, but if exact pre/in/post-order is required, the recursive version is simpler.

BFS vs. DFS — When to Use Which

Scenario Prefer Why
Shortest path (unweighted) BFS BFS guarantees shortest distance by level expansion
Connectivity / cycle detection Either Both visit all reachable nodes
Topological sort DFS (or Kahn's BFS) DFS post-order gives reverse topological order
Path finding / backtracking DFS Natural fit for exploring and undoing choices
Level-order / wave expansion BFS Processes all nodes at same distance together
