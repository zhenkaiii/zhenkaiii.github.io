When to reach for a heap

Core idea: heap = when you repeatedly need the min or max of something. Two flavors:

  • "K-th largest / top-K" — fixed-size heap, gatekeeper pattern (Problems 1-2, 6, 8)
  • "What's the current smallest/largest among active things?" — heap grows and shrinks dynamically (Meeting Rooms II, Merge K Lists, Task Scheduler)

Why heap beats sorting: Sorting is O(n log n). A heap of size K gives you O(n log K). When K « n, log K « log n. You only keep the K elements you care about — everything else gets rejected at the gate.

The core rule: the gatekeeper

"K-th largest? That's a heap. By default Python gives you a min-heap, so use a min-heap with a fixed size K. Walk through the array: if the heap isn't full yet, keep enrolling candidates. When it's full, consider replacing — if the new guy is bigger than the current gatekeeper (the root), swap him in. Otherwise ignore."

for each candidate:
    if heap not full   → push                              O(log k)
    if new > root      → pop + push (swap in the legit)    O(log k)
    else               → ignore                            O(1)

Most candidates get rejected at O(1) — one comparison against the root. Only legit candidates pay the O(log k) sift cost. That's why it's O(n log k) not O(n log n).

GoalHeap typeSizeRoot (gatekeeper) isReplace when
K largest min-heap K smallest of the K largest new > root
K smallest max-heap (negate) K largest of the K smallest new < root

Python heapq is min-heap only. For max-heap, negate values. Don't negate when you don't need to — for K-largest, use a min-heap directly on original values. Negation only when you need max-heap behavior (K-smallest, or the lower half in two-heap median).

heapq cheat sheet

A heap is always a plain list. Not a set, not a dict. Just a list that heapq keeps in heap order.

import heapq

h = []
heapq.heappush(h, 5)          # push
heapq.heappop(h)               # pop smallest
h[0]                            # peek (smallest), O(1)
heapq.heapify(lst)             # list → heap in-place, O(n)

heappush / heappopO(log n)
heapifyO(n)

Controlling the sort key: use tuples

There's no key= parameter like sorted(). Instead, you control what it sorts by using tuples. Python compares tuples element by element — first element first, second as tiebreaker, and so on.

# Sort by value — just push the value
heapq.heappush(h, 5)

# Sort by frequency — (sort_key, data)
heapq.heappush(h, (freq, key))          # e.g. (3, "apple")

# Sort by distance — (sort_key, extra, extra)
heapq.heappush(h, (dist, x, y))         # e.g. (18, 3, 3)

# Problem 2: top-K frequent → sort by freq
heapq.heappush(heap, (cnt, key))         # min of cnt = gatekeeper

# Problem 3: merge K lists → sort by node value
heapq.heappush(heap, (node.val, idx, node))

# Problem 4: meeting rooms → sort by end time
heapq.heappush(rooms, end_time)

The tiebreaker trap

If two tuples have the same first element, Python compares the second. If the second element isn't comparable (like a ListNode), you get a crash. Fix: insert a unique integer as tiebreaker.

# BAD:  (1, ListNode) vs (1, ListNode) → crash, can't compare ListNode
# GOOD: (1, 0, ListNode) vs (1, 1, ListNode) → tiebreak on idx, never reaches ListNode

This is why Problem 3 (merge K lists) uses (node.val, idx, node) — the idx is a unique tiebreaker so Python never tries to compare ListNode objects.

Problem 1: K-th Largest Element in Array

Pattern: K-largest → min-heap of size K. Root = answer.
Example: [3,2,1,5,6,4], k=2 → 5
Time: O(n log k)   Space: O(k) 
def findKthLargest(nums, k):
    heap = []                          # min-heap, size capped at k
    for x in nums:
        if len(heap) < k:
            heapq.heappush(heap, x)
        elif x > heap[0]:              # bigger than current k-th? replace
            heapq.heappop(heap)
            heapq.heappush(heap, x)
                                       # else: too small, ignore
    return heap[0]                     # root = k-th largest

Trace: [3,2,1,5,6,4], k=2

x=3: heap=[3]           (size < k, push)
x=2: heap=[2,3]         (size < k, push)
x=1: 1 > 2? no, ignore  heap=[2,3]
x=5: 5 > 2? yes, replace heap=[3,5]
x=6: 6 > 3? yes, replace heap=[5,6]
x=4: 4 > 5? no, ignore  heap=[5,6]
return heap[0] = 5 ✓

Problem 2: Top-K Frequent Elements

Pattern: Frequency map → min-heap of size K ordered by freq.
Example: [1,1,1,2,2,3], k=2 → [1,2]
Time: O(n + u log k) where u = unique keys   Space: O(u) 
def topKFrequent(nums, k):
    freq = {}
    for x in nums:
        freq[x] = freq.get(x, 0) + 1

    heap = []                              # min-heap by frequency
    for key, cnt in freq.items():
        if len(heap) < k:
            heapq.heappush(heap, (cnt, key))
        elif cnt > heap[0][0]:             # more frequent? replace
            heapq.heappop(heap)
            heapq.heappush(heap, (cnt, key))

    return [key for cnt, key in heap]

Problem 3: Merge K Sorted Lists

Pattern: Min-heap of K list heads. Pop smallest, push its successor.
Example: 1→4→5, 1→3→4, 2→6 → 1→1→2→3→4→4→5→6
Time: O(N log k) where N = total nodes   Space: O(k)

Linked list building pattern (memorize this)

To build a linked list you need two pointers:

  • dummy — created once, never moves. Only purpose: give you a stable head to return at the end.
  • tail — the workhorse. Advances every time you append a node. This is the one that grows the list.
dummy = ListNode(0)       # fake head, used once
tail = dummy              # tail does all the work

# append a node:
tail.next = node          # attach after current tail
tail = tail.next          # advance tail

# when done, return the real list (skip fake head):
return dummy.next

# Result:  dummy → A → B → C → None
#            ↑                    ↑
#        never moves         tail ends here

The solution

def mergeKLists(lists):
    heap = []
    for idx, node in enumerate(lists):
        if node:
            heapq.heappush(heap, (node.val, idx, node))

    dummy = ListNode(0)                              # fake head
    tail = dummy                                     # tail of result list
    while heap:
        val, idx, node = heapq.heappop(heap)         # pop smallest
        tail.next = node                             # append to result
        tail = tail.next                             # advance tail
        if node.next:                                # push successor
            heapq.heappush(heap, (node.next.val, idx, node.next))

    return dummy.next                                # skip fake head

The idx in the tuple is a tiebreaker — ListNode isn't comparable, so without it Python crashes when two nodes have the same value.

Problem 4: Meeting Rooms II

Problem: Given a list of meetings [start, end], find the minimum number of conference rooms needed so no two overlapping meetings share a room.
Pattern: Sort by start time. Min-heap tracks end times of active rooms.
Example: [[0,30],[5,10],[15,20]] → 2 rooms
Time: O(n log n)   Space: O(n) 
Timeline:
Room 1: |████████████████████████████████████| [0,30]
Room 2:      |█████|                           [5,10]
                        |█████|                [15,20] ← reuses Room 2 (10 ≤ 15)

Why heap: The heap stores end times of rooms currently in use. The root = the room that frees up earliest. For each new meeting: if it starts after the root (earliest end), that room is free — pop it and push the new end time (reuse). Otherwise, push a new end time (new room). Heap size at the end = number of rooms needed.

def minMeetingRooms(intervals):
    intervals.sort(key=lambda x: x[0])     # sort by start
    rooms = []                              # min-heap of end times

    for start, end in intervals:
        if rooms and rooms[0] <= start:     # earliest room is free?
            heapq.heappop(rooms)            # free the room
            heapq.heappush(rooms, end)      # reuse it
        else:
            heapq.heappush(rooms, end)      # need a new room

    return len(rooms)

[5,10]:  rooms[0]=30 > 5   → no free → push 10. rooms=[10,30]   2 rooms
[15,20]: rooms[0]=10 ≤ 15 → free! pop+push 20.  rooms=[20,30]   2 rooms (reused)
return len(rooms) = 2 ✓

Trace: [[1,5],[2,3],[4,6],[7,8]]

[2,3]: rooms[0]=5 > 2     → no free → push 3.  rooms=[3,5]     2 rooms

return len(rooms) = 2 ✓

Problem 5: Median from Data Stream (Two Heaps)

Pattern: Max-heap (lower half) + min-heap (upper half). Median at the roots.
Invariant: sizes differ by at most 1. All of max-heap ≤ all of min-heap.
Time: O(log n) per add, O(1) per median 
class MedianFinder:
    def __init__(self):
        self.lo = []    # max-heap (negated) — lower half
        self.hi = []    # min-heap — upper half

    def addNum(self, num):
        # Step 1: route to correct heap
        if self.lo and num <= -self.lo[0]:
            heapq.heappush(self.lo, -num)
        else:
            heapq.heappush(self.hi, num)

        # Step 2: rebalance (sizes differ by at most 1)
        if len(self.lo) - len(self.hi) > 1:
            heapq.heappush(self.hi, -heapq.heappop(self.lo))
        if len(self.hi) - len(self.lo) > 1:
            heapq.heappush(self.lo, -heapq.heappop(self.hi))

    def findMedian(self):
        if len(self.lo) == len(self.hi):
            return (-self.lo[0] + self.hi[0]) / 2
        elif len(self.lo) > len(self.hi):
            return -self.lo[0]
        else:
            return self.hi[0]

Problem 6: K Closest Points to Origin

Pattern: K-smallest distances → max-heap of size K (negate distances).
Example: [[3,3],[5,-1],[-2,4]], k=2 → [[3,3],[-2,4]]
Time: O(n log k) 
def kClosest(points, k):
    heap = []                                  # max-heap (negated dist)
    for x, y in points:
        dist = x*x + y*y                      # no need for sqrt
        if len(heap) < k:
            heapq.heappush(heap, (-dist, x, y))
        elif -dist > heap[0][0]:               # closer? replace farthest
            heapq.heappop(heap)
            heapq.heappush(heap, (-dist, x, y))

    return [[x, y] for _, x, y in heap]

K-smallest uses a max-heap of size K. The root is the farthest of the K closest — if a new point is closer, it kicks the farthest out.

Problem 7: Task Scheduler

Pattern: Max-heap of task counts + cooldown queue.
Example: ["A","A","A","B","B","B"], n=2 → 8 (A B idle A B idle A B)
Time: O(total_intervals × log 26) 
from collections import Counter, deque

def leastInterval(tasks, n):
    freq = Counter(tasks)
    heap = [-cnt for cnt in freq.values()]     # max-heap of counts
    heapq.heapify(heap)
    cooldown = deque()                          # (count_remaining, available_at)
    time = 0

    while heap or cooldown:
        time += 1
        if heap:
            cnt = heapq.heappop(heap) + 1       # +1 because negated (one task done)
            if cnt < 0:                          # still tasks remaining
                cooldown.append((cnt, time + n)) # can't reuse until time+n
        if cooldown and cooldown[0][1] == time:
            heapq.heappush(heap, cooldown.popleft()[0])

    return time

Problem 8: Kth Largest in a Stream

Pattern: Persistent min-heap of size K across streaming adds.
Example: k=3, init=[4,5,8,2]. add(3)→4, add(5)→5, add(10)→5
Time: O(n log k) init, O(log k) per add 
class KthLargest:
    def __init__(self, k, nums):
        self.k = k
        self.heap = []
        for x in nums:
            self.add(x)

    def add(self, val):
        if len(self.heap) < self.k:
            heapq.heappush(self.heap, val)
        elif val > self.heap[0]:
            heapq.heappop(self.heap)
            heapq.heappush(self.heap, val)
        return self.heap[0]

Same logic as Problem 1, but the heap persists across calls. The root is always the k-th largest seen so far.

Problem 9: Dead Language Tokenizer (Mozilla Interview)

Problem: Given a Latin text corpus, build a tokenizer for the 500 most frequent words. Assign each a unique int ID; unknown words map to -1.
Pattern: HashMap counting → min-heap of size 500 (top-K frequent) → HashMap for ID lookup.
Time: O(n) counting + O(n log 500) heap   Space: O(n)
Source: Mozilla ML Engineer interview (CoderPad, 25 min)

This is a real interview problem that combines two patterns: HashMap counting (step 1) and min-heap top-K (step 2). It's essentially Problem 2 (Top-K Frequent Elements) applied to NLP tokenization.

Full solution

import heapq

# ── Step 1: Count word frequencies (HashMap) ──────────────
word_count = {}
for word in latin_text.split():                # don't forget .split()!
    word_count[word] = word_count.get(word, 0) + 1

# ── Step 2: Top-500 via min-heap (gatekeeper pattern) ─────
heap = []                                       # min-heap, size capped at 500
for word, cnt in word_count.items():
    if len(heap) < 500:
        heapq.heappush(heap, (cnt, word))       # (count, word) — sort by count!
    elif cnt > heap[0][0]:                      # more frequent than gatekeeper?
        heapq.heappop(heap)
        heapq.heappush(heap, (cnt, word))

# ── Step 3: Assign unique IDs (second HashMap) ───────────
token_map = {}
token_id = 0
for cnt, word in heap:
    token_map[word] = token_id
    token_id += 1

# ── Step 4: Tokenize function ────────────────────────────
def tokenize(text):
    result = []
    for word in text.split():
        if word in token_map:
            result.append(token_map[word])      # known → ID
        else:
            result.append(-1)                   # unknown → -1
    return result

Why this is a heap problem

The corpus may have tens of thousands of unique words, but we only care about the top 500. Sorting all of them would be O(n log n). The min-heap of size 500 gives us O(n log 500) — and log 500 ≈ 9 is practically constant.

This is exactly Problem 2 (Top-K Frequent Elements) with K=500. The heap tuple is (cnt, word) — count first so the heap sorts by frequency, not alphabetically.
