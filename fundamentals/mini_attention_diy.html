The Shape Story (MHA)

This is how you talk through it in an interview. Trace every shape.

Input: x (B, T, D) Project: q = W_q(x) (B, T, D) ← init doesn't split heads! k = W_k(x) (B, T, D) v = W_v(x) (B, T, D) Split: q.reshape (B, T, H, d_k) q.transpose (B, H, T, d_k) ← swap T and H Logits: q @ k.T (B, H, T, d_k) @ (B, H, d_k, T) → (B, H, T, T) d_k disappears! logits are raw, unnormalized. Weights: softmax(logits / √d_k, dim=-1) (B, H, T, T) Now probabilities — each row sums to 1. Context: weights @ v (B, H, T, T) @ (B, H, T, d_k) → (B, H, T, d_k) d_k is back! q, k, v, context all share (B, H, T, d_k). Merge: .transpose (B, T, H, d_k) .reshape (B, T, D) ← heads merged back Output: W_o(context) (B, T, D)

V1: Vanilla Single-Head Attention

class MyMultiheadAttentionV1(nn.Module):
    # Most vanilla attention — single head, no reshape!
    def __init__(self, d_model):
        super().__init__()
        self.q = nn.Linear(d_model, d_model)
        self.k = nn.Linear(d_model, d_model)
        self.v = nn.Linear(d_model, d_model)
        self.o = nn.Linear(d_model, d_model)

        self.d_model = d_model

    def forward(self, x):
        q_val = self.q(x)                          # (B, T, D)
        k_val = self.k(x)                          # (B, T, D)
        v_val = self.v(x)                          # (B, T, D)

        # (B, T, D) @ (B, D, T) → (B, T, T)  — these are logits (raw, pre-softmax)
        logits = (q_val @ k_val.transpose(-1, -2)) / self.d_model ** 0.5
        attn_weights = F.softmax(logits, dim=-1)  # now probabilities

        return self.o(attn_weights @ v_val)
Works but wastes capacity. Every position uses full d_model for one attention pattern. Multi-head lets you attend to different things in parallel.

V2: Multi-Head Attention

class MyMultiheadAttentionV2(nn.Module):
    # MHA — split into heads in forward, not init!
    def __init__(self, d_model, n_head):
        super().__init__()
        # Init doesn't split heads! Full d_model projections.
        self.q = nn.Linear(d_model, d_model)
        self.k = nn.Linear(d_model, d_model)
        self.v = nn.Linear(d_model, d_model)
        self.o = nn.Linear(d_model, d_model)

        self.n_head = n_head
        self.d_k = d_model // n_head

    def forward(self, x):
        q_val = self.q(x)                          # (B, T, D)
        k_val = self.k(x)
        v_val = self.v(x)

        # Split heads on all three Q, K, V
        B, T, D = q_val.size()

        q_val = q_val.reshape(B, T, self.n_head, self.d_k).transpose(1, 2)
        k_val = k_val.reshape(B, T, self.n_head, self.d_k).transpose(1, 2)
        v_val = v_val.reshape(B, T, self.n_head, self.d_k).transpose(1, 2)
        # All three: (B, H, T, d_k)

        # (B, H, T, d_k) @ (B, H, d_k, T) → (B, H, T, T): d_k dropped!
        logits = (q_val @ k_val.transpose(-1, -2)) / self.d_k ** 0.5
        attn_weights = F.softmax(logits, dim=-1)  # logits → probabilities
        # (B, H, T, T) @ (B, H, T, d_k) → (B, H, T, d_k): d_k back!
        # Except for attn_weights, q/k/v/context all share (B, H, T, d_k).
        context = attn_weights @ v_val

        # Merge heads back: reverse of split
        context = context.transpose(1, 2).reshape(B, T, D)
        return self.o(context)

V3: Grouped Query Attention (GQA)

Fewer KV heads than Q heads. Saves KV cache memory. Used in LLaMA 2 70B, Mistral, etc.

Example: 32 Q heads, 8 KV heads → each KV head is shared by 4 Q heads → 4x KV cache reduction.

GQA Shape Story

Project: q = W_q(x) (B, T, D) ← full size, same as MHA k = W_k(x) (B, T, n_kv * d_k) ← smaller! v = W_v(x) (B, T, n_kv * d_k) ← smaller! Split: q.reshape (B, H, T, d_k) ← H = n_head (e.g. 32) k.reshape (B, H', T, d_k) ← H' = n_kv_heads (e.g. 8) Expand: k.repeat (B, H, T, d_k) ← repeat each KV head H/H' times This is the key line! Now K,V match Q's head count. Rest is identical to MHA.
class MyMultiheadAttentionV3(nn.Module):
    # GQA — fewer KV heads, Q heads grouped and shared
    def __init__(self, d_model, n_head, n_kv_heads):
        super().__init__()
        # n_kv_heads: the new hyperparam!
        # e.g. n_head=32, n_kv_heads=8 → 4 Q heads share each KV head
        self.n_kv_heads = n_kv_heads
        self.n_head = n_head
        self.d_k = d_model // n_head
        self.d_model = d_model

        # Q stays full size. K, V shrink!
        self.q = nn.Linear(d_model, d_model)
        self.k = nn.Linear(d_model, self.n_kv_heads * self.d_k)  # smaller
        self.v = nn.Linear(d_model, self.n_kv_heads * self.d_k)  # smaller
        self.o = nn.Linear(d_model, d_model)

    def forward(self, x):
        q_val = self.q(x)                          # (B, T, D)
        k_val = self.k(x)                          # (B, T, n_kv * d_k) — smaller!
        v_val = self.v(x)                          # (B, T, n_kv * d_k) — smaller!

        B, T, D = q_val.size()

        # Q splits into full n_head, K/V split into n_kv_heads
        q_val = q_val.reshape(B, T, self.n_head, self.d_k).transpose(1, 2)        # (B, H, T, d_k)
        k_val = k_val.reshape(B, T, self.n_kv_heads, self.d_k).transpose(1, 2)   # (B, H', T, d_k)
        v_val = v_val.reshape(B, T, self.n_kv_heads, self.d_k).transpose(1, 2)   # (B, H', T, d_k)

        # THE KEY LINE: expand KV heads to match Q heads
        # repeat_interleave on dim=1 (head dim). Tensor method, NOT F.!
        # n_head // n_kv_heads = group size (how many Q heads share one KV head)
        k_val = k_val.repeat_interleave(self.n_head // self.n_kv_heads, dim=1)   # (B, H, T, d_k)
        v_val = v_val.repeat_interleave(self.n_head // self.n_kv_heads, dim=1)   # (B, H, T, d_k)

        # From here, identical to MHA
        # (B, H, T, d_k) @ (B, H, d_k, T) → (B, H, T, T): d_k dropped!
        logits = (q_val @ k_val.transpose(-1, -2)) / self.d_k ** 0.5
        attn_weights = F.softmax(logits, dim=-1)  # logits → probabilities
        # (B, H, T, T) @ (B, H, T, d_k) → (B, H, T, d_k): d_k back!
        context = attn_weights @ v_val

        context = context.transpose(1, 2).reshape(B, T, D)
        return self.o(context)
V2 → V3 diff is only 3 things: (1) K,V projections shrink in init. (2) K,V reshape uses n_kv_heads not n_head. (3) repeat_interleave to expand back. Everything else is identical.

Level 4: Cross-Attention

Q from target modality (e.g., video), K/V from conditioning modality (e.g., audio). Only change: K and V project from cond, not x.

class MyCrossAttention(nn.Module):
    def __init__(self, d_model, d_cond, n_head):
        super().__init__()
        self.q = nn.Linear(d_model, d_model)
        self.k = nn.Linear(d_cond, d_model)       # K from conditioning!
        self.v = nn.Linear(d_cond, d_model)       # V from conditioning!
        self.o = nn.Linear(d_model, d_model)

        self.n_head = n_head
        self.d_k = d_model // n_head

    def forward(self, x, cond):
        # x: (B, T_video, D)   cond: (B, T_audio, D_cond)
        q_val = self.q(x)                          # (B, T_video, D)
        k_val = self.k(cond)                       # (B, T_audio, D)
        v_val = self.v(cond)                       # (B, T_audio, D)

        B, T_v, D = q_val.size()
        T_a = k_val.size(1)

        q_val = q_val.reshape(B, T_v, self.n_head, self.d_k).transpose(1, 2)
        k_val = k_val.reshape(B, T_a, self.n_head, self.d_k).transpose(1, 2)
        v_val = v_val.reshape(B, T_a, self.n_head, self.d_k).transpose(1, 2)

        # (B, H, T_v, d_k) @ (B, H, d_k, T_a) → (B, H, T_v, T_a)
        logits = (q_val @ k_val.transpose(-1, -2)) / self.d_k ** 0.5
        attn_weights = F.softmax(logits, dim=-1)  # logits → probabilities
        # (B, H, T_v, T_a) @ (B, H, T_a, d_k) → (B, H, T_v, d_k)
        context = attn_weights @ v_val

        context = context.transpose(1, 2).reshape(B, T_v, D)
        return self.o(context)
Self-attn vs cross-attn: the only code diff is where K and V come from. The attention math is identical.

Burn-In Rules

  • Init doesn't split heads. Projections are full d_model → d_model. Splitting happens in forward via reshape.
  • All three Q, K, V get reshaped — not just Q and K.
  • reshape to split, transpose to swap. Don't mix them up. reshape(B, T, H, d_k) then transpose(1, 2).
  • Scale by √d_k, not √d_model. Each head has dimension d_k.
  • @ for matmul, not *. * is element-wise.
  • .transpose(-1, -2) for K, not .T. .T flips all dims.
  • Unmerge = reverse of split: transpose(1, 2) then reshape(B, T, D).
  • Naming: before softmax = logits (raw). After softmax = attn_weights (probabilities).
  • Logits/weights shape (B, H, T, T) — d_k disappears. Context brings it back.
  • repeat_interleave is a tensor method, not F. — call it on the tensor directly.
  • GQA repeat count = n_head // n_kv_heads, not n_kv_heads or d_model // n_kv_heads.

Bonus: Adding a Causal Mask

For autoregressive models (LLMs), prevent attending to future tokens.

# Create mask: lower triangular = 1, upper = 0
mask = torch.tril(torch.ones(T, T, device=x.device))   # (T, T)

# Apply before softmax: -inf where mask is 0
logits = logits.masked_fill(mask == 0, float('-inf'))
attn_weights = F.softmax(logits, dim=-1)
After softmax, -inf becomes 0 — future tokens get zero attention weight.

Golden 1 Min

MHA Walkthrough

For multi-head self-attention, like most PyTorch modules, you need __init__ and forward. I like to think through the forward logic first, then figure out what needs to be initialized.

Attention has four weight matrices: Q, K, V, and O. O is just the output projection — straightforward. Q, K, and V are the core components used to compute the attention score and context. For self-attention, the same input goes into all three.

So in forward, the input goes through the Q, K, and V linear layers to get three activations. For multi-head, you reshape each one to split out the heads, then transpose so the shape becomes batch, heads, sequence length, head dimension.

Now the attention score: Q times K-transpose, divided by the square root of the head dimension for scaling. That goes through softmax along the last dimension to get the attention weights — shape is batch, heads, S, S. The head dimension is gone because Q and K-transpose contracted over it.

Multiply the score by V to get the context. Transpose the heads and sequence dimensions back, reshape to the original shape, and pass through the output projection. That's it.

In __init__, you just need four linear layers for Q, K, V, O, and store the number of heads and the per-head dimension.

class MHA(nn.Module):
    def __init__(self, dim, n_heads):
        super().__init__()
        self.q = nn.Linear(dim, dim)
        self.k = nn.Linear(dim, dim)
        self.v = nn.Linear(dim, dim)
        self.o = nn.Linear(dim, dim)

        self.n_heads = n_heads
        self.d_k = dim // self.n_heads

    def forward(self, x):
        q = self.q(x)
        k = self.k(x)
        v = self.v(x)

        B, S, _ = q.size()

        q = q.reshape(B, S, self.n_heads, self.d_k).transpose(1, 2)  # B, H, S, K
        k = k.reshape(B, S, self.n_heads, self.d_k).transpose(1, 2)  # B, H, S, K
        v = v.reshape(B, S, self.n_heads, self.d_k).transpose(1, 2)  # B, H, S, K

        score = F.softmax((q @ k.transpose(-1, -2)) / self.d_k ** 0.5, dim=-1)  # B, H, S, S

        context = score @ v

        context = context.transpose(1, 2).reshape(B, S, -1)

        return self.o(context)  # B, S, D

Why Q, K, V — and Why KV Cache

Q is always about the current token — it's the query being asked right now. There's no caching Q because it changes every step during autoregressive decoding.

K and V are the database. K is the index — what each past token advertises for matching. V is the content — what actually gets passed along when matched. During inference, this database grows by one entry every step, and it never changes for past tokens. That's why we cache it.

All the major inference optimizations target K and V because that's where the memory bottleneck is. KV cache quantization compresses the stored entries. GQA reduces the number of KV heads so there are fewer entries to store per layer. Sliding window attention caps the database size so it doesn't grow forever. They all share the same purpose: shrink the KV database that accumulates during autoregressive decoding.

Q stays untouched by all of this — it's just one token's question, computed fresh every step.
