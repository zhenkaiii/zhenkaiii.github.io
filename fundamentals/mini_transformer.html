Mini Transformer Block + Training Loop

PyTorch Transformer Interview Prep

The Block

One transformer block = Self-Attention + FFN, each wrapped in pre-norm + residual.

x ─────────────────────────────┐ │ │ residual 1 ├─▶ LayerNorm ─▶ MHA ─────────┘ │ (Q=K=V=x) x ─────────────────────────────┐ │ │ residual 2 ├─▶ LayerNorm ─▶ FFN ─────────┘ │ (Linear → SiLU → Linear) x ─▶ out Shape through entire block: (B, T, D) → (B, T, D) (never changes)

Burn-In Rules

  • super().__init__() — always first line in __init__
  • import torch.nn.functional as F — functional, no 's', lowercase
  • self.mha(h, h, h) — MHA needs Q, K, V explicitly. Returns (output, weights), discard weights with _
  • Two residuals, each from its own sublayer. Second residual is from post-MHA, NOT from original x
  • Two norms, one per sublayer. Don't reuse.
  • FFN: d_model → d_ff (4x) → d_model. Use nn.Sequential
  • batch_first=True on nn.MultiheadAttention for (B, T, D) input

Complete Code

import torch
import torch.nn as nn
import torch.nn.functional as F  # functional, no 's'


class MiniTransformerBlock(nn.Module):
    def __init__(self, d_model, d_ff, n_head):
        super().__init__()  # always first line
        self.mha = nn.MultiheadAttention(d_model, n_head, batch_first=True)
        self.mlp = nn.Sequential(
            nn.Linear(d_model, d_ff),
            nn.SiLU(),
            nn.Linear(d_ff, d_model),
        )
        self.norm_1 = nn.LayerNorm(d_model)  # one norm per sublayer
        self.norm_2 = nn.LayerNorm(d_model)

    def forward(self, x):
        # x: (B, T, D)
        h = self.norm_1(x)
        h, _ = self.mha(h, h, h)  # self-attn: Q=K=V, discard weights
        x = x + h                  # residual 1

        h = self.norm_2(x)
        h = self.mlp(h)
        x = x + h                  # residual 2
        return x

Gated FFN Variant (LLaMA / SwiGLU)

LLaMA uses 3 linear layers instead of 2. gate and up are parallel, then multiplied. Can't use nn.Sequential — needs a custom module.

class GatedFFN(nn.Module):
    def __init__(self, d_model, d_ff):
        super().__init__()
        self.gate = nn.Linear(d_model, d_ff)
        self.up   = nn.Linear(d_model, d_ff)
        self.down = nn.Linear(d_ff, d_model)

    def forward(self, x):
        return self.down(F.silu(self.gate(x)) * self.up(x))
Use via composition, not inheritance: self.mlp = GatedFFN(d_model, d_ff)

Training Loop on Random Data

You need 3 things before the loop: data, model, optimizer. Loss is computed inside.
# --- Setup ---
random_data = torch.randn(32, 128, 4096)  # (B, T, D)
model = MiniTransformerBlock(4096, 16384, 16)
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)

# --- Loop ---
for i in range(20):
    optimizer.zero_grad()                          # clear grads
    idx = torch.randint(0, 32, (4,))               # sample mini-batch
    trn_x = random_data[idx]

    trn_y = trn_x[:, 1:, :]                        # target: next token
    pred = model(trn_x[:, :-1, :])                  # input: drop last

    loss = F.mse_loss(pred, trn_y)
    loss.backward()                                 # compute grads
    optimizer.step()                                # update weights

    if i % 5 == 0:
        print(f"step {i:3d} | loss {loss.item():.4f}")

Training Loop Rules

StepCodeWhy
1. Clear gradsoptimizer.zero_grad()PyTorch accumulates grads by default
2. Forwardpred = model(x)
3. Lossloss = F.mse_loss(pred, y)MSE for regression, no dim arg
4. Backwardloss.backward()Computes gradients on all params
5. Stepoptimizer.step()Updates weights using grads
Order: zero_grad → forward → loss → backward → step. Getting this wrong is an instant red flag.

Golden 1 Min

class Model(nn.Module):
    def __init__(self, feat_dim, hidden_dim):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(feat_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, feat_dim),
        )
    def forward(self, x):
        return self.net(x)

The most primitive example of designing a model and writing a training loop looks like this. Here I have a simple MLP — two linear layers with a ReLU activation in between. These three modules are chained together using nn.Sequential, and I call it net. That's the architecture.

The forward pass is straightforward — the input x goes through the net, and whatever comes out is the model's output.

For the training loop, you define three things: the model, the data, and the optimizer. Inside the for loop, you first call zero_grad to clear the gradients from the previous iteration — so each iteration starts with a clean slate. Then you feed the input through the model to get a prediction, compute the loss against the ground truth using MSE, and call backward to compute gradients. Finally, optimizer.step updates the model parameters. That's it — that's the entire training loop.
