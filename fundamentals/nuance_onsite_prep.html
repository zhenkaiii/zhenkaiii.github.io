1. Contrastive Loss / CLIP from Scratch Priority #1

This is the gap Claudia exposed. She gave you two tasks: (1) train an MLP to predict text embedding from image embedding with MSE loss — you nailed this in 35 min. (2) Map both modalities into a shared space where matching pairs are close. You correctly identified that naive MSE collapses to constant output (zero loss but meaningless), and you knew contrastive/triplet loss was the fix, but admitted you haven't implemented it. Fix that today.
  • Implement two MLP encoders mapping image/text embeddings to shared space
  • Compute cosine similarity matrix (B, B) between image and text outputs
  • InfoNCE loss: cross-entropy where correct pairs are on the diagonal
  • Know cold: why MSE collapses (constant output gets zero loss), why contrastive doesn't (negative pairs prevent collapse)
  • Know the difference: CLIP/InfoNCE = whole batch, (B,B) similarity matrix, cross-entropy on diagonal. Triplet loss = anchor + positive + negative, one pair at a time. CLIP is the modern standard.

CLIP Loss in 10 Lines

# img_emb, txt_emb: (B, D) — outputs from two encoders
img_emb = F.normalize(img_emb, dim=-1)
txt_emb = F.normalize(txt_emb, dim=-1)

# similarity matrix: (B, B) — each row is one image vs all texts
logits = img_emb @ txt_emb.T / temperature    # scale by temperature

# labels: correct pair is on the diagonal — index i matches index i
labels = torch.arange(B, device=logits.device)

# symmetric loss: image→text + text→image
loss = (F.cross_entropy(logits, labels) + F.cross_entropy(logits.T, labels)) / 2

That's it. The diagonal of the similarity matrix should be highest. Cross-entropy pushes correct pairs up, all other pairs down. No collapse possible because pushing everything to constant makes the off-diagonal just as high as the diagonal.

2. Whiteboard Presentation — LLM Pretraining at Amazon 20-25 min

This is the most important part of the onsite. You present your best, most relevant work on a whiteboard. Pick LLM pretraining — it's the rarest experience you have and shows you build from zero at scale.

Narrative arc: We needed to train Amazon's Nova foundation model (MoE architecture, competitor to Gemini). I was hands-on, training 100+ models across different scales up to 1k+ GPUs.

Draw on the whiteboard: MoE architecture diagram, data pipeline flow, distributed training setup (DDP across nodes).

Key lessons to highlight:

  • Data quality > architecture. Fixing deduplication and format issues gave bigger marginal gain than tuning hyperparameters or enabling fancy tricks like block masking.
  • Small dense models for ablation. Don't waste 1k GPUs testing a hypothesis. Use a 1-2B dense model to validate data quality, then scale up. Faster iteration, cheaper.
  • Block masking + data packing for efficient pretraining — pack multiple sequences into one context window, mask attention so they don't attend to each other.
  • Experiment velocity matters most. The team that runs more experiments wins. Infra, logging, reproducibility, leaderboards — all of this accelerates learning.

Practice: On paper/whiteboard, not slides. Out loud. Twice. Time it — cut anything over 25 min.

3. Light Tech Stack Review

Their JD lists these. You don't need to be an expert, but should speak fluently about what each does and trade-offs.

  • vLLM — open-source LLM serving engine. Key feature: PagedAttention (manages KV cache like virtual memory pages, avoids fragmentation). High throughput for batched LLM inference. Use when serving a standard LLM. TensorRT-LLM is NVIDIA's alternative — faster but less flexible, harder to customize.
  • Triton Inference Server — NVIDIA's model serving framework. Handles batching, model versioning, multi-model serving on same GPU. Think of it as the orchestration layer for deploying models in production.
  • WebRTC — real-time audio/video streaming protocol. Peer-to-peer, sub-200ms latency. This is how user's webcam/mic connects to their system. The constraint: everything downstream (ASR, LLM, DiT) must fit within WebRTC's latency budget or the conversation feels laggy.
  • Kubernetes — container orchestration. For them: scheduling GPU pods, scaling inference replicas, managing model deployments. Know the basics: pods, deployments, services, GPU resource requests.
