Two Pointer & Sliding Window

Scholar LinkedIn CV

The Gist

Both two-pointer and sliding window avoid O(n²) brute force by exploiting structure to skip work. The core idea:

  • Two pointers: use sorted order or sequential constraints to eliminate pairs you don't need to check.
  • Sliding window: maintain a window state incrementally — don't recompute from scratch for every subarray. Expand right every step. Shrink left only when invalid. Each element enters and exits at most once → O(n).

Two Pointers: Opposite Ends

Start with lo = 0 and hi = n - 1, move them inward. Works on sorted arrays. Move the pointer that gets you closer to the goal.

LC 167: Given a sorted array [2, 7, 11, 15] and target = 9, find two numbers that add up to target. Return their indices. → [0, 1] 

def two_sum_sorted(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        s = nums[lo] + nums[hi]
        if s == target:
            return [lo, hi]
        elif s < target:
            lo += 1      # sum too small, need larger value
        else:
            hi -= 1      # sum too large, need smaller value

Two Pointers: Same Direction (Fast & Slow)

Both pointers start at the beginning. Fast scans every element; slow only advances when a condition is met.

LC 26: Given sorted array [0, 0, 1, 1, 1, 2, 2, 3], remove duplicates in-place and return the new length. → 4 (array becomes [0, 1, 2, 3, ...]) 

def remove_duplicates(nums):
    if not nums:
        return 0
    slow = 0
    for fast in range(1, len(nums)):
        if nums[fast] != nums[slow]:
            slow += 1
            nums[slow] = nums[fast]
    return slow + 1

Sliding Window: Fixed Size

Window size k is given. Slide across the array, updating a running aggregate in O(1) per step.

Example: Given [2, 1, 5, 1, 3, 2] and k = 3, find the maximum sum of any contiguous subarray of size 3. → 9 (subarray [5, 1, 3]) 

def max_sum_subarray(nums, k):
    window_sum = sum(nums[:k])
    best = window_sum

    for i in range(k, len(nums)):
        window_sum += nums[i] - nums[i - k]   # add right, drop left
        best = max(best, window_sum)

    return best

Sliding Window: Variable Size

This is the core pattern. The window has no fixed size — it grows and shrinks to find the optimal (longest or shortest) subarray satisfying a constraint. The template: 

left = 0
state = ...     # tracks the window (Counter, sum, set, etc.)
best = ...

for right in range(len(arr)):
    # 1. Expand: add arr[right] into state

    # 2. Shrink: while window is invalid, remove arr[left] from state
    while invalid(state):
        # remove arr[left] from state
        left += 1

    # 3. Record best

Like binary search, the template is always the same. The only thing that changes per problem:

What changes Per-problem decision
State What do you track in the window? (Counter, sum, set, ...)
Invalid condition When must you shrink? (duplicate found, sum exceeds k, missing chars, ...)
Record when? Want longest? Record after shrinking (window is valid). Want shortest? Record while shrinking (window just became valid).

State Reference

The template is always the same. The creative part is choosing the state — what data structure captures whether the window is valid?

Problem keyword State Invalid when
"without repeating" / "distinct" Counter (char → count) any count > 1
"at most k distinct" Counter (char → count) len(counter) > k
"sum ≤ target" int (running sum) window_sum > target
"contains all chars of t" Counter + missing int missing > 0 (still need chars)
"max consecutive ones with k flips" int (zero count) zero_count > k

Variable Window: Longest

LC 3: Given string "abcabcbb", find the length of the longest substring without repeating characters. → 3 ("abc") 

def length_of_longest_substring(s):
    count = {}
    left = 0
    best = 0

    for right in range(len(s)):
        count[s[right]] = count.get(s[right], 0) + 1   # 1. Expand
        while count[s[right]] > 1:                      # 2. Shrink
            count[s[left]] -= 1
            left += 1
        best = max(best, right - left + 1)              # 3. Record

    return best

Variable Window: Shortest

LC 76: Given s = "ADOBECODEBANC" and t = "ABC", find the smallest window in s that contains all characters of t. → "BANC" 

from collections import Counter

def min_window(s, t):
    need = Counter(t)
    missing = len(t)         # total chars still needed
    left = 0
    best = (0, float('inf'))

    for right in range(len(s)):
        if need[s[right]] > 0:
            missing -= 1
        need[s[right]] -= 1

        while missing == 0:              # valid: window contains all of t
            if right - left < best[1] - best[0]:
                best = (left, right)     # record WHILE shrinking
            need[s[left]] += 1
            if need[s[left]] > 0:
                missing += 1
            left += 1

    start, end = best
    return s[start:end+1] if end < float('inf') else ""

How to Talk About It

Variable sliding window:

"I'll use a sliding window with two pointers. I expand right every step and track [state] in the window. When [invalid condition], I shrink from the left until the window is valid again. I record the best [longest/shortest] valid window. Each element enters and exits the window at most once, so this is O(n)."

Two pointers (opposite ends):

"The array is sorted, so I'll use two pointers starting from both ends. If the sum is too small I move the left pointer right; if too large I move the right pointer left. Each step eliminates one candidate, so this is O(n)."

Pattern Pointer Motion Typical Signal
Opposite-ends lo++ / hi-- Sorted input, pair/triplet search

Variable window Expand right, shrink left "Longest/shortest substring/subarray with constraint"

Common Pitfalls

  • Subarray/substring = contiguous. Sliding window only works for contiguous ranges. If the problem says "subsequence" (not contiguous), sliding window doesn't apply.
  • Monotonicity required. Sliding window works when expanding can only make the window "more invalid" and shrinking can only make it "more valid." If elements can be negative (e.g., subarray sum = k), this breaks — use prefix sum + hash map instead.
  • Order is expand → shrink → record. You must add the new element first to know whether the window became invalid. Shrink-first only works in special cases (e.g., set-based peek). Stick with expand first.
  • lo < hi vs. lo <= hi. Two pointers (opposite ends) uses lo < hi because you need two distinct elements. Sliding window allows left == right (window of size 1 is valid).
  • Shrinking removes collateral. When shrinking to fix a duplicate, you remove everything between left and the offending element — not just the duplicate itself. The window must stay contiguous.
