Sort-First Strategy

Many problems become straightforward once the input is sorted. The mental test: "Would a sorted order let me make a single-pass decision?" If yes, sort first — O(n log n) sorting rarely dominates the overall complexity.

Problem Type Sort By Then
Interval merge / overlap Start time Linear scan, extend or close intervals
Meeting rooms Start time Heap or sweep to track concurrent meetings
Assign tasks to workers Difficulty or deadline Greedy assignment
Closest pair / duplicates Value Compare adjacent elements

Merge Intervals

Sort by start, then greedily extend the current interval or start a new one: 

def merge(intervals):
    intervals.sort()
    merged = [intervals[0]]

    for start, end in intervals[1:]:
        if start <= merged[-1][1]:       # overlap
            merged[-1][1] = max(merged[-1][1], end)
        else:
            merged.append([start, end])  # gap — new interval

    return merged

Key insight: after sorting by start, two intervals overlap iff the current start ≤ the previous end. No need to check all pairs.

Insert Interval

Given sorted, non-overlapping intervals and a new interval, insert and merge: 

def insert(intervals, new):
    result = []
    i = 0
    n = len(intervals)

    # 1. Add all intervals ending before new starts
    while i < n and intervals[i][1] < new[0]:
        result.append(intervals[i])
        i += 1

    # 2. Merge all overlapping intervals with new
    while i < n and intervals[i][0] <= new[1]:
        new[0] = min(new[0], intervals[i][0])
        new[1] = max(new[1], intervals[i][1])
        i += 1
    result.append(new)

    # 3. Add remaining
    result.extend(intervals[i:])
    return result

Meeting Rooms (Min Rooms Needed)

Sort by start time, use a min-heap to track end times of ongoing meetings. If the earliest-ending meeting has ended before the new one starts, reuse that room: 

import heapq

def min_meeting_rooms(intervals):
    intervals.sort()
    heap = []  # end times of active meetings

    for start, end in intervals:
        if heap and heap[0] <= start:
            heapq.heapreplace(heap, end)  # reuse room
        else:
            heapq.heappush(heap, end)     # need new room

    return len(heap)

Sweep Line

An alternative to the heap approach: decompose each interval into two events (+1 at start, -1 at end), sort all events, and sweep through. The running total at any point equals the number of concurrent intervals. 

def max_concurrent(intervals):
    events = []
    for start, end in intervals:
        events.append((start, +1))
        events.append((end, -1))

    events.sort()    # ties broken by type: -1 before +1 (ending before starting)

    concurrent = 0
    max_concurrent = 0
    for _, delta in events:
        concurrent += delta
        max_concurrent = max(max_concurrent, concurrent)

    return max_concurrent

When to use sweep line over heap? Sweep line is simpler when you only need the max concurrency count. The heap approach is better when you need to track which rooms / resources are in use.

Custom Sort Keys

Python's sort is stable (preserves order of equal elements) and accepts a key function: 

# Sort by end time (for greedy interval scheduling)
intervals.sort(key=lambda x: x[1])

# Sort by multiple criteria: primary ascending, secondary descending
tasks.sort(key=lambda x: (x[0], -x[1]))

# Sort strings by length, then lexicographically
words.sort(key=lambda w: (len(w), w))

For the non-overlapping intervals (activity selection) problem, sort by end time and greedily pick the earliest-ending non-conflicting interval.
